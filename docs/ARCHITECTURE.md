# Backend Architecture

> Status: **v1.0, approved design for phase B2.** This document says *how* the backend is built.
> *What* it does is decided elsewhere and is not re-decided here:
>
> | Question | Source of truth |
> |---|---|

## 1. Processes and containers

One Go binary, `netopology`, runs as several containers (IDEA.md §14):

| Command | Container | Does | Talks to |
|---|---|---|---|
| `netopology api` | `api` | REST + SSE under `/api/v1`, sessions, authorization, redaction. Runs migrations on start (behind an advisory lock) unless `NETOPOLOGY_MIGRATE_ON_START=false`. | db |
| `netopology worker` | `worker` | River job queue: housekeeping now; health polling, workflow runs, plugin installs later. | db, sandbox (C3+) |
| `netopology migrate` | one-off | goose migrations + River's tables, as the schema-owner role. | db |
| `netopology openapi` | — | Prints the OpenAPI generated from the Go code. | — |

```
browser ──► gateway (nginx) ──┬──► web (Next.js, UI only)
                              └──► api ──► db (PostgreSQL 18)  ◄── worker ──► sandbox (C3)
            networks: edge = gateway, web, api · core (internal) = api, worker, db · sandbox = worker, sandbox
```

`api` and `worker` share the code and the database. **They never call each other over HTTP.** The
api enqueues River jobs in the same transaction as the change that needs them; the worker writes
results to the database and emits live events (§9) exactly like the api does.

## 3. Request lifecycle

```
chi middleware (all routes)          Recoverer → RequestContext (request id, real IP) → AccessLog
/api/v1 middleware                   SameOrigin (CSRF) → auth.Middleware (cookie → Principal)
Huma                                 parse + validate path/query/header/body against the Go input struct
feature handler                      call ONE service method
feature service                      authorize → pg.InWorkspace{ queries + audit + event } → map to wire type
Huma                                 serialize output; errors → problem+json via httpx.InstallErrors
```

- **Validation that the contract can express** (lengths, patterns, enums, required, min/max) is
  done by Huma from struct tags, before the handler runs. Services validate only what the contract
  cannot express (e.g. "placeOn must be a canvas you were granted"), and return `apperr.Invalid`.
- **Huma body limit** is 1 MB by default; keep it unless an operation needs more (`MaxBodyBytes`).

## 4. Layers and package rules

| Layer | File | May | Must not |
|---|---|---|---|
| Handler | `handler.go` | Declare the operation with `httpx.Op`, define input/output structs, call one service method, return its error unchanged | Touch SQL/pgx (lint-enforced), contain `if role == ...`, build problem bodies |
| Service | `service.go` (+ topic files) | Authorize, enforce rules, run transactions, write audit + events, redact, map rows → wire types | Know about HTTP (no `net/http` except `http.Cookie` passthrough), log-and-return the same error |
| Store | `db/queries/<feature>.sql` → `dbgen` | Express data access as named SQL | Contain authorization decisions |
| Model | `model.go` | Wire types (request/response bodies) of this feature | Logic beyond small mapping helpers |

There is **no separate `store.go`** unless a feature needs composite data logic (e.g. building the
canvas view from several queries). sqlc's generated `dbgen.Queries` *is* the store.

**Feature isolation.** A feature package never imports another feature package. Shared needs go
through, in this order of preference: (1) `platform/*`, (2) `authz`, (3) `apimodel` for shared wire
types, (4) a small interface defined by the *consumer* and wired in `server.features()` (see
`setup.SessionStarter`). Example: `canvas` needs inventory redaction → `canvas` declares
`type InventoryReader interface{...}`, `server` passes the `*inventory.Service`.

## 5. Database access

### 5.1 Roles and RLS

| Role | Used by | Properties |
|---|---|---|
| `postgres` | container admin, tests (creates throwaway DBs) | superuser, never used by the app |
| `netopology_owner` | `netopology migrate` | owns the schema; `BYPASSRLS` so `SECURITY DEFINER` maintenance functions work |
| `netopology_app` | `api`, `worker` | `NOSUPERUSER NOBYPASSRLS`: RLS applies. `pg.Open` refuses to start otherwise. |

Workspace-owned tables (`areas nodes links notes canvases canvas_grants placements canvas_shapes
workspace_events`) have `FORCE ROW LEVEL SECURITY` with the policy
`workspace_id = current_workspace_id()`, where `current_workspace_id()` reads the transaction-local
setting `app.workspace_id`.

### 5.2 The three ways to run SQL (`internal/platform/pg`)

```go
db.Q()                                   // no transaction; single reads of NON-RLS tables only
db.Tx(ctx, func(q *dbgen.Queries) error) // transaction, no workspace (users, sessions, workspaces, members, share_links, settings)
db.InWorkspace(ctx, wsID, func(q *dbgen.Queries) error) // transaction scoped to one workspace: ALL workspace content
```

Rules:
1. **Every query on a workspace-owned table filters by `workspace_id` in SQL**, even though RLS would
   hide other rows. RLS is the backstop for our bugs, not the access check.
2. **A mutation, its audit entry and its event are written in the same transaction.** Either all
   three happen or none does.
3. Do slow work (argon2id, outbound HTTP) **before** opening the transaction.
4. Never hold a transaction across a network call to anything but Postgres.

### 5.3 sqlc conventions

- One file per feature: `db/queries/<feature>.sql`. Name queries `VerbNoun` (`GetNode`, `ListNodesForCanvas`, `UpdateNode`).
- `:one` returning nothing → `pg.IsNotFound(err)` → `apperr.ErrNotFound()`.
- Optimistic concurrency: `UPDATE ... WHERE workspace_id = $1 AND id = $2 AND version = $3 RETURNING *`;
  no row → re-read: missing = 404, otherwise 412 (`apperr.PreconditionFailed()`). `touch_versioned()`
  bumps `version` and `updated_at` automatically.
- Lists use keyset pagination on the UUIDv7 id: `WHERE id > sqlc.narg(after) ORDER BY id LIMIT $n`,
  fetch `limit+1` to know if there is a next page; `nextCursor = httpx.EncodeCursor(lastID)` or null.
- Translate constraint errors in the service: `pg.UniqueViolation(err)` → `slug.taken` etc.;
  `pg.TriggerError(err)` → the trigger's message as `apperr.Conflict("canvas.invalid_operation", msg)`.
- JSONB columns are `json.RawMessage`; validate their shape in the service (properties are an array
  of `Field`, settings/style objects) before writing.
- After changing SQL: `task gen:sqlc`. Generated code is committed.

### 5.4 Migrations

- goose files `db/migrations/NNNNN_name.sql`, next free number, `-- +goose Up` / `-- +goose Down`.
  Wrap functions/DO blocks in `-- +goose StatementBegin/End`.
- New workspace-owned table ⇒ in the same migration: `workspace_id uuid NOT NULL`, composite FKs
  `(workspace_id, x_id)`, index, `ENABLE` + `FORCE ROW LEVEL SECURITY`, `workspace_isolation` policy.
- Never edit a merged migration. Add a scenario to `db/tests/scenarios.sql` for every new trigger/constraint.

## 6. Authentication

### 6.1 Sessions (implemented: `internal/auth/session.go`, `middleware.go`)
- Cookie `netopology_session`: 256-bit random token, `HttpOnly; Secure; SameSite=Lax; Path=/`.
  The table stores only `sha256(token)`.
- `auth.Middleware` resolves the cookie on every `/api/v1` request to an `authz.Principal`
  (anonymous if missing/expired/disabled user). It never rejects; operations decide.
- Sliding expiry: `last_seen_at`/`expires_at` refreshed at most once a minute.
- **Lifetimes** (contract `LoginRequest.remember`):
  | | Cookie | Server-side expiry (sliding) |
  |---|---|---|
  | `remember: false` (default; also setup and OAuth sign-in) | session cookie (no `Max-Age`, ends with the browser) | `sessionTtlHours` (instance setting, default 168 h; `NETOPOLOGY_SESSION_TTL` until WP-04 adds the setting) |
  | `remember: true` | persistent, `Max-Age` = lifetime | `max(30 days, sessionTtlHours)`: constant `auth.RememberTTL = 30 * 24 * time.Hour` |
  Migration `00004_session_remember.sql` adds `sessions.remember boolean NOT NULL DEFAULT false`;
  the middleware's touch extends `expires_at` by **that session's** lifetime, never a single global TTL.
- Logout deletes the row and clears the cookie. Password reset / disabling an account deletes all
  of that user's sessions (`DeleteUserSessions`).

### 6.2 Password login (WP-03)
- `crypto.VerifyPassword`; unknown username → `crypto.DummyVerify` (same timing), same 401
  `auth.invalid_credentials` for both cases. Disabled account → same 401.
- Rate limit in memory (single api process; documented): per IP 20/min and per username 10/15min,
  token bucket in `internal/auth/ratelimit.go`; exceeding → `apperr.RateLimited(seconds)` (429 + Retry-After).
- On success: `NeedsRehash` → re-hash; `Sessions.Start`; audit `auth.login` (failed attempts are
  audited too, with `metadata.reason`, never the password).

### 6.3 Google / Discord (WP-05)
- Authorization-code flow with PKCE via `golang.org/x/oauth2`. `start` sets a signed
  (`crypto.Signer` purpose `"oauth"`) cookie `netopology_oauth` holding
  `{state, verifier, mode: "login"|"link", userId?, returnTo}` for 10 minutes, then 302 to the provider.
- `callback` verifies state, exchanges the code, fetches the profile (Google: OIDC userinfo `sub`,
  `email`, `email_verified`; Discord: `/users/@me` `id`, `email`, `verified`).
- `login` mode: identity linked → sign in. Not linked → if `oauthAutoLinkByEmail` and the
  provider-**verified** email equals exactly one active account's email and that account has no
  identity for this provider → link + sign in. Otherwise 401 `auth.identity_not_linked`. **Never
  create an account** (no self-signup, permissions.md rule 10).
- `link` mode (from `/me/identities/{provider}/link`, requires a session): link to the signed-in user;
  identity already linked elsewhere → 409 `auth.identity_in_use`.
- The callback always ends with a 302 to the web app (`/` or `returnTo`, same-origin paths only),
  with `?error=<code>` on failure. Redirect URI: `PUBLIC_URL/api/v1/auth/oauth/{provider}/callback`.

### 6.4 Guests (WP-12)
- `POST /share/{token}/unlock` checks the token (and password if set), then sets `netopology_share`
  = signed (`purpose "share"`) `{shareLinkId, passwordVersion}`; `Path=/api/v1/share; SameSite=Strict`.
- A share middleware on `/share/*` routes resolves it to `Principal{Guest: &GuestGrant{...}}`
  after re-checking the link is not revoked/expired. Guests never get a session and every non-share
  endpoint treats them as anonymous (→ 401).

## 7. Authorization

`internal/authz/permission.go` encodes the permission table (permissions.md §3) as scopes + role sets.
`TestPermissionKeys` keeps it identical to the contract's `x-permission` keys.

| Scope | Check at the top of the service method |
|---|---|
| Anonymous | nothing |
| Account | `p, err := authz.RequireSignedIn(ctx)` |
| Instance | `p, err := authz.RequireInstanceStaff(ctx)` (+ the SO/SA rules in the notes) |
| Workspace | `actor, err := s.authz.Actor(ctx, wsID, authz.NodeUpdate)` |
| Guest | share middleware already resolved the grant; check `p.Guest.CanvasID` |

`Resolver.Actor` returns **404 for non-members** (never 403: rule 2) and **403 `role.insufficient`**
when the role lacks the permission. After that, the service applies the "service rules" listed in
the comments of `permission.go`. They are all in permissions.md §2/§3; the important ones:

- **Editor visibility set (rule 3)**, owned by `inventory` (WP-08) and reused by `canvas`, `share`, `events`:
  ```
  canvases  = granted tab canvases (canvas_grants)  ∪  inner canvases of visible areas placed on them (rule 11)
  nodes     = nodes placed on those canvases
  areas     = areas placed on those canvases ∪ areas referenced by visible nodes (name only)
  links     = links whose BOTH endpoints are visible nodes
  notes     = notes attached to visible nodes/links/areas, notes placed on visible canvases,
              notes attached to visible canvases, workspace-level notes
  ```
  Implement it as SQL (one CTE per set, in `db/queries/inventory.sql`), not as Go loops over all
  rows. Out-of-set items are **404**. Owners, admins and viewers skip this (they see everything).
- **placeOn (rule 4)**: editor creates of node/area/note must include `placeOn` = a granted canvas;
  missing → 422 `inventory.place_on_required`; not granted → 404.
- **Rule 5**: editor delete of an item placed on any canvas outside their grants → 409 `inventory.used_elsewhere`.
- **Rule 6 protected**: delete or clearing `isProtected` → owner only (`403 protected`);
  admin may set it; editor may not change it.
- **Rule 7 owners vs admins** and **last owner** (`409 member.last_owner`, checked with
  `SELECT ... FOR UPDATE` on the owner rows to avoid races).
- **Rule 8 locked canvas**: `canvas.edit` on a locked canvas → 423 `canvas.locked`.

## 8. Redaction

Implemented once, in `inventory` (WP-08), as pure functions over the wire types:

```go
type Audience struct{ Sensitive bool; Guest bool } // from Actor.SeesSensitive() or a guest grant
func redactNode(n *Node, a Audience)   // sensitive fields: value removed + redacted:true; guests: field omitted
func redactNote(n *Note, a Audience) bool // false = omit (guest + sensitive)
func redactArea(a *Area, aud Audience) // cidr, vlanId
```

Every read path (list, get, canvas view, shared view, SSE event data) calls them. **Never return a
sensitive value and rely on the frontend to hide it.** Table-driven unit tests cover every row of
permissions.md §4.

## 9. Live updates (SSE)

```
service, inside pg.InWorkspace:  events.Emit(ctx, q, events.Change{Type: events.NodeUpdated, SubjectID: &id, CanvasIDs: ...})
  └─ INSERT workspace_events → trigger → pg_notify('netopology_events', '<ws>:<eventId>')  (delivered on COMMIT only)
api process: events.Broker  LISTEN → Ref{ws, eventId} → every Subscription of that workspace
GET /workspaces/{wsId}/events (internal/events, WP-11):
  1. authz.Actor(ctx, wsId, EventsStream); if Last-Event-ID → replay ListWorkspaceEventsAfter first
  2. for each Ref: load the event row; skip if ?canvasId= given and not in canvas_ids;
     load the subject AS THIS ACTOR through the owning service's read method (visibility + redaction);
     404 → skip silently (or send {id} for *.deleted); write `id:`, `event:`, `data:` (contract Event)
  3. heartbeat comment every 25 s; end when the client disconnects or the subscription is closed
     (client reconnects with Last-Event-ID).
```
Events older than 24 h are pruned by the worker (`prune_workspace_events`).

## 10. Audit log

`auditlog.Write(ctx, q, auditlog.Entry{...})` inside the mutation's transaction. One entry per
successful mutating operation; `Action` = the operation's permission key. Also audit: login success
and failure, logout, OAuth sign-in/link, share-link unlock (as `share_link` actor). Do not audit reads.
**Metadata never contains secrets** (passwords, tokens, credentials): record changed field *names*.

## 11. Errors

Services return `*apperr.Error` (`Kind` + stable `Code` + safe `Detail`); handlers return it unchanged;
`httpx.InstallErrors` renders the contract's `Problem` (`application/problem+json`). Any other error is
a 500 with a generic message, and is logged with the request id.

| Kind | Status | Common codes |
|---|---|---|
| Invalid | 422 | `validation`, `inventory.place_on_required` |
| Unauthenticated | 401 | `auth.required`, `auth.invalid_credentials`, `auth.identity_not_linked`, `share.password_required` |
| Forbidden | 403 | `role.insufficient`, `protected`, `origin.mismatch` (middleware) |
| NotFound | 404 | `not_found` (also for "you may not know it exists") |
| Conflict | 409 | `setup.already_completed`, `slug.taken`, `member.last_owner`, `inventory.used_elsewhere`, `auth.last_sign_in_method`, `auth.identity_in_use` |
| PreconditionFailed | 412 | `version.stale` |
| Locked | 423 | `canvas.locked` |
| RateLimited | 429 | `rate_limited` (+ `Retry-After`) |

Codes are API surface: add to `apperr` constants when used by more than one feature, never rename.

## 12. Writing a feature: the recipe

`internal/setup` is the reference. For a workspace-scoped mutation the shape is:

```go
// model.go: wire types named exactly like the contract schemas
type NodeUpdate struct { Name *string `json:"name,omitempty" minLength:"1" maxLength:"100"`; ... }

// handler.go
huma.Register(api, httpx.Op(authz.NodeUpdate, http.MethodPatch, "/workspaces/{wsId}/nodes/{nodeId}",
	"updateNode", "Nodes", "Update a node", httpx.Errors(403, 404, 409, 412, 422)), h.update)

type updateInput struct {
	WsID    uuid.UUID `path:"wsId"`
	NodeID  uuid.UUID `path:"nodeId"`
	IfMatch string    `header:"If-Match"`
	Body    NodeUpdate
}
type nodeOutput struct {
	ETag string `header:"ETag"`
	Body Node
}
func (h *Handler) update(ctx context.Context, in *updateInput) (*nodeOutput, error) {
	n, err := h.svc.UpdateNode(ctx, in.WsID, in.NodeID, in.IfMatch, in.Body)
	if err != nil { return nil, err }
	return &nodeOutput{ETag: httpx.ETag(n.Version), Body: n}, nil
}

// service.go
func (s *Service) UpdateNode(ctx context.Context, wsID, id uuid.UUID, ifMatch string, in NodeUpdate) (Node, error) {
	actor, err := s.authz.Actor(ctx, wsID, authz.NodeUpdate)          // 404 non-member, 403 role
	if err != nil { return Node{}, err }
	version, conditional, err := httpx.IfMatch(ifMatch)
	if err != nil { return Node{}, err }
	var out Node
	err = s.db.InWorkspace(ctx, wsID, func(q *dbgen.Queries) error {
		cur, err := s.visibleNode(ctx, q, actor, id)                    // 404 outside the editor's set
		if err != nil { return err }
		if err := checkProtectedChange(actor, cur, in); err != nil { return err } // rule 6
		row, err := q.UpdateNode(ctx, ...)                             // WHERE version = $n when conditional
		if pg.IsNotFound(err) { return apperr.PreconditionFailed() }
		if err != nil { return err }
		if err := auditlog.Write(ctx, q, auditlog.Entry{WorkspaceID: &wsID, Action: authz.NodeUpdate,
			TargetType: "node", TargetID: &id, Metadata: map[string]any{"fields": changedFields(in)}}); err != nil { return err }
		if err := events.Emit(ctx, q, events.Change{WorkspaceID: wsID, Type: events.NodeUpdated,
			SubjectID: &id, CanvasIDs: canvasesShowing(ctx, q, id)}); err != nil { return err }
		out = toNode(row, actor)                                         // redaction applied here
		return nil
	})
	return out, err
}
```

Checklist per operation (the contract test enforces the first four):
1. `httpx.Op` values identical to the contract (path, method, operationId, tag, summary, permission).
2. Success status (`httpx.Status(201)` for creates, 204 for empty deletes) and declared error statuses.
3. Go type names = contract schema names; json names, required and nullable as in the contract.
4. Parameters: same names, `in`, required.
5. Authorization first; every applicable service rule; 404-not-403 for invisibility.
6. Mutations: one transaction with audit + event; `ETag` on versioned resources; `If-Match` honored.
7. Integration tests through `testutil.NewAPI` covering success, each rule, and the role matrix rows.

## 13. Background jobs

River (`internal/worker`). Add a job = args type with `Kind()` + worker type embedding
`river.WorkerDefaults[T]`, registered in `worker.Run`. Enqueue from the api inside the business
transaction with `river.ClientFromContext`/an insert-only client (add when the first such job
exists). Jobs touching workspace data use `pg.InWorkspace` and audit as `system`.

## 14. Testing

See [TESTING.md](TESTING.md). In short: unit tests for pure logic (redaction, policy helpers);
**integration tests through the real HTTP stack and a real Postgres** for every operation
(`testutil.NewAPI(t)`); the contract test; the permission matrix (permissions.md §5) as its own
test file per feature. No mocks of the database.

## 15. Configuration

Environment only, parsed once in `config.Load()`, documented in [ENVIRONMENT.md](ENVIRONMENT.md)
and `.env.example`. Add a variable = add it in all three places.

## 16. Security checklist (reviewers check every PR)

- [ ] Workspace content only via `pg.InWorkspace`, SQL filtered by `workspace_id`.
- [ ] Authorization at the top of every service method; non-members get 404.
- [ ] Redaction applied on every read path, including events and shared views.
- [ ] No secrets in logs, audit metadata, error details, URLs we log. Credentials write-only.
- [ ] Passwords: argon2id via `crypto`; tokens: `crypto.NewToken`, stored hashed.
- [ ] Cookies only via `httpx.Cookies`. Redirect targets restricted to same-origin paths.
- [ ] New table: RLS + composite FKs + scenarios.
- [ ] No `fmt.Sprintf` into SQL (sqlc only; the test harness is the single exception).

## 17. Decisions (and why)

| Decision | Why |
|---|---|
| Contract stays hand-written; Go must match it (contract test) | The frontend already builds against it; agents can implement operations in any order without drifting. `api/openapi.gen.yaml` shows what is really served. Once all 72 operations exist (`task test:strict` green), the generated file becomes the frontend's source. |
| Errors via a Huma error hook, services return `apperr` | Handlers stay one-liners; services stay HTTP-free; every error has a stable code. |
| Events: transactional outbox + LISTEN/NOTIFY, re-read per subscriber | No event can describe an uncommitted change, and redaction/visibility are exactly those of a GET with zero extra code. |
| Schema owner has BYPASSRLS, app role has not | Retention jobs can run as `SECURITY DEFINER` functions without giving the app role any bypass. |
| Tests use a real Postgres via template databases, not testcontainers | Works with any Postgres (local, remote, CI service), ~50 ms per isolated DB, no Docker-in-test requirement. |
| Dev tools pinned in `tools/go.mod`, run via `go tool` | No global installs, same versions for every contributor and agent; sqlc's pure-Go build needs no cgo or Docker. |
| In-memory login rate limit | Single api process in v1. Revisit (Postgres table) if the api is ever scaled out. |
